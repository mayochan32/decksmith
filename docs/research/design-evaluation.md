# デザイン品質の比較検証

## 何を成功とするか

利用者が気にしている「ダサい・変」を、主役が不明、図の意味が不正確、揃えと間隔が不安定、指定スタイルを外す、資料全体が単調、といった観察へ分ける。評価項目は研究用であり、製品に特定の見た目を強制するものではない。

最初に内容保持・事実・図の意味・判読性の重大問題を判定する。ここに失敗した出力は、見た目の平均点が高くても採用しない。その上で次を各1〜5点と具体的な観察で評価する。1＝用途を満たさない、3＝読めるが修正したい、5＝この用途でそのまま使いたい。該当しない図解項目はN/Aとし、図解を使わないことを減点しない。

| 観点 | 比較時に見ること |
| --- | --- |
| 主役と読み順 | 何を伝えるページか、次にどこを読むか |
| 図解の適切さ | 関係・方向・条件が正しく、本文の理解を助けるか |
| 文字・揃え・余白 | 日本語の改行、文字階層、対応する位置、まとまり |
| スタイルへの忠実さ | 色以外の指定も表れ、素材や書体が内容に合うか |
| 資料全体 | 呼称・色の役割・論理の一貫性と、構図の変化 |

## 比較の組み方

1. 現状の実出力と好みの参考資料を同程度の目的・言語・情報量で集める。まず10〜15ページ程度を候補にし、比較・関係図・説明密度の違う代表3ページを固定する。異なる内容の見栄えだけで優劣を決めない。
2. 原稿、必須文字、元スタイル、素材、スライド数、描画環境を固定する。基準版mainのコミットと候補版のコミットを記録する。条件の異なる美しい参考資料は、改善の着眼点として使い、A/Bの得点には混ぜない。
3. 同じモデル・設定・生成回数・修正予算で、独立した生成文脈から旧ガイド／新ガイドを比較する。新ガイドを既に読んだAIが旧版を装ったり、意図的に劣化させたbeforeを作ったりしない。独立生成ができない試作は「適用例」と明示する。
4. 各案を匿名のA/Bとして左右を入れ替えて提示し、好み、理由、使うために必要な修正を記録する。生成担当者自身の判定と、利用者の判定を区別する。未回答を同点・合格にしない。
5. 改善を見てから選んだ題材だけで終わらず、下記の反例を保留用の題材で試す。生成回数、所要時間、修正回数、失敗数も残す。

## 必ず試す反例

| 入力 | 保持すべき振る舞い |
| --- | --- |
| 6つの独立した必須条件 | 6つを保持。3項目化・偽の循環・意味のない四象限を作らない |
| 3段階の一方向手順 | 終了地点を保持。始点へ戻る矢印を追加しない |
| 未解決時だけ差し戻す運用 | 戻る条件と対象を示す。常時循環にしない |
| 比較対象ごとに制約が異なる | 差異と条件を保持。見た目の対称性で条件を落とさない |
| 短い主張・引用だけのページ | 図解を無理に挿入しない |
| 同じ原稿＋未知の日本語キーを含む2スタイル | 色だけでなく文字・線・構図が変わり、原稿と関係は変わらない |
| 必須画像／多い文字量／既定と逆の配置 | 設計上の目安で画像・内容・元指定を消さない |

## mainへのマージ判定

候補版の調整前に、今回の受入基準として以下を使う。これは実証済みの普遍的な数値基準ではない。

- 内容の欠落、虚偽の関係、読めない主要ラベル、必須スタイルや画像の無断変更がない。
- 独立生成の代表3ページ中2ページ以上で利用者が候補版を選び、残りに重大な悪化がない。資料全体も確認する。
- 別題材・別スタイルと反例でも、内容保持とスタイル解釈が後退しない。
- 既存テスト、Skill検証、通常配布物への同梱・単独実行確認が通る。
- 生成・修正コストが増えた場合は改善との釣り合いを記録し、利用者が受容できる。

結果表では「実施済み／未実施／利用者判定待ち」を明示する。満たすまでは開発ブランチを維持する。設計ガイドの整備や技術的な動作確認だけでmainへマージしない。

## 結果記録の雛形

比較ID、日時、原稿・style・素材の指紋、旧／新コミット、モデル・生成条件、描画環境、初稿と修正版、全PNG、内容検査結果、上記5観点の観察、利用者の選択と理由、生成時間・修正回数、未解決事項をまとめる。再現入力は残すが、利用者の参考資料・全文抽出・図版はリポジトリへ追加しない。
