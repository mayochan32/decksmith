# 設計原則の適用例・検証記録

実施日：2026-10-10〜11。基準版：mainの`e33da14`（v0.9.0）。

**生成ガイドへの組み込みと、2スタイル・計8ページの適用確認まで実施した。旧版に対する品質向上の実証は未実施であり、mainにはマージしていない。**

## 取り込んだもの

[設計技法と組み込み先](communication-design-principles.md)に、原稿から要素と関係を判断する、主役と読み順を設計する、書体・線・色の役割を揃える、といった原則を整理した。既存の内容保持・スタイル解釈・視覚検証へ接続し、生成前と描画後の判断に使う。

## 適用例の条件

架空の「問い合わせ対応の試行案」を使った。4ページの表示文40項目は両スタイルで同一とし、sceneを作る前に原稿由来の内容基準を固定した。画像なし、restricted、provided_onlyで、外部素材取得・画像生成・外部API呼び出しは行っていない。

| ページ | 確認したこと |
| --- | --- |
| 主張 | 短い文章で伝わる場合に図解を追加しない。効果未検証の条件を残す |
| 比較 | 窓口・割当・記録の同じ観点を対応させる。時間短縮を捏造しない |
| 経路 | 未解決時だけ担当から受付へ戻す。完了からの循環を作らない |
| 六条件 | 全項目と説明を保持する。順序・因果・順位を付けない |

paperは明るい紙色、明朝見出し、朱色、左右の比較、横方向の経路。nightは濃色、太いゴシック、青緑、上下の比較、下から右へ進む経路。同じ表示文を保ちながら、文字・線・配置を変えた。元スタイルは独自の日本語キーを持つ。

これは新ガイドを読んだAIが内容に合わせて設計した作例である。再現用スクリプトは設計済み座標を保存しており、任意の原稿からデザインを自動選択する機能でも、旧版との独立生成A/Bでもない。

描画はMac上のLibreOfficeとPoppler。Microsoft PowerPoint実機・Windowsでの表示確認は未実施。レビュー検査の通過は、成果物との対応と確認記録が揃ったことを示すもので、美しさの自動判定ではない。

この試作ではPPTXを計4回生成した（初稿2本、修正版2本）。視覚修正は1巡。所要時間・モデル設定を管理した独立比較ではないため、生成コストの改善率も算出していない。

## mainへのマージ前に残ること

[比較検証の手順](design-evaluation.md)に従い、現行出力と好みの参考資料から代表題材を選ぶ。同じ原稿・スタイル・生成条件で、旧ガイドと新ガイドの出力を独立した生成文脈で作り、利用者の比較評価を得る。現行版を装った劣化作例は作らない。

別題材での保留用検証も残る。一方向の手順、非対称な比較条件、必須画像、多い文字量などは今回の作例だけでは確認できていない。Windowsでの表示、修正コストと品質の釣り合いも確認する。現時点の判定は「適用例は確認済み、品質向上は未判定」。
