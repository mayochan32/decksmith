# 内容を伝えるための設計原則と組み込み先

初版：2026-10-10。更新：2026-10-11。基準版はmainの `e33da14`（v0.9.0）。

目的は「何を伝えるための図か」を生成前に判断し、生成後も同じ観点で確認できるようにすること。既存の内容保持・自由なスタイル解釈・視覚検証に、図解と読み順の判断を組み合わせる。モデルの追加学習ではなく、生成AIが読む指示と設計・レビュー記録の改善である。

## 技法と具体的な適用

| 設計技法 | 生成時の判断・動作 | 確認すること | 主な組み込み先 |
| --- | --- | --- | --- |
| 問いと答えを先に定める | 聞き手が何を知りたいか、原稿が何を答えられるかを決める。提案なら目的・判断を早く示す | 未確定の効果を断定せず、結論と根拠がつながる | communication-designの「先に伝える関係」、planのaudience_question / takeaway |
| 要素と関係から図解を選ぶ | 比較、順序、循環、階層、交差などを原稿の意味で区別し、図の要否も選ぶ | 独立項目に矢印を足さない。戻り条件や終点を保つ | SKILLの工程4、communication-designの判断表、planのrelationship / source_basis |
| 意味のまとまりで整理する | 最初に把握するまとまりを減らす。ただし項目数を上限にせず、必須情報を残す | 六条件を三つに削る、根拠のない上位分類を作る、といった変更がない | communication-designの情報整理、既存の内容基準との照合 |
| 主役と読み順を設計する | 主張・差分・関係を目立たせ、根拠・条件へ読める配置にする | 章番号や装飾が主張に勝たず、図から意図した関係を読める | communication-designの「主役」「読み順」、design-planのfocal_element / composition / communication |
| 基準線と余白で関係を示す | 比較対象やラベルの位置を揃え、関連するまとまりの間に余白を置く | 箱の座標だけでなく実際の字面が揃い、線と文字が重ならない | communication-designの「揃えと余白」、quality-gatesの視覚確認 |
| 色と書体の役割を統一する | 基調・補助・強調の役割、見出し・本文・注記の階層を保つ。構図は内容に応じて変える | 同じ対象の色が途中で変わらず、同じカード列の反復だけにならない | communication-designの「色の役割」「統一と変化」、既存のtypography / signatures、全体レビュー |
| 目的に合うデータ表現を選ぶ | 比較・推移・構成比など、読むべき内容に合うグラフを選び注目点を示す | 単位・期間・母数を残し、面積・立体効果・尺度で誇張しない | communication-designの判断表と「数値と証拠」。必要なネイティブグラフ実装は既存のSKILL条件に従う |
| 資料全体の論理を点検する | 問い・答え・根拠・具体化のつながりと、ページ間の構図の変化を設計する | タイトル列と一覧で飛躍・重複・呼称の不一致を確認する | quality-gatesの視覚確認工程4、communication-designの全体レビュー |
| 利用場面に合わせて密度を決める | 投影・配布・説明の役割を考え、利用者の文字量と構成の指定を優先する | 必須内容を無断でノートに移さず、単独で読む資料にも対応する | 既存のdesign-planの文字設計、quality-gatesの文字量照合を維持 |

## 実行経路

1. [SKILL.mdの工程4](../../skills/decksmith/SKILL.md)で、座標設計の前に[内容と図解の判断](../../skills/decksmith/references/communication-design.md)を読む。
2. [design-plan](../../skills/decksmith/references/design-plan.md)に従い、各ページの聞き手の問い、伝える関係、根拠、選んだ表現、読み順、避ける誤読をcommunicationメモへ残す。
3. その判断をsceneの文字・図形・線・位置へ具体化し、既存の描画エンジンでPPTXとプレビューを生成する。
4. [quality-gates](../../skills/decksmith/references/quality-gates.md)の視覚確認で、プレビューから読める関係を原稿と照合する。意味の誤りはcontent、読みにくさはlegibility、スタイルとの差はstyleの証拠としてreview.jsonに記録する。

新規の中心は、図解の意味を判断するガイドとcommunicationメモ、およびその判断を完成画像のレビューへ接続する部分。文字役割・必須内容・スタイル台帳などは既存の仕組みを使い、確認観点を補強した。

communicationメモは自由記述であり、意味や美しさを機械的に採点するスキーマではない。Pythonや描画エンジンに図の意味を推測させたり、完成レイアウトの固定メニューを追加したりはしていない。

## 適用例と適用しないルール

架空の問い合わせ運用案で、図解不要の主張、同条件の比較、未解決時だけの戻り経路、六つの独立条件を試した。同じ表示文を明るい紙面と濃色の二つのスタイルで配置し、文字と線が重なる箇所を画像確認で修正した。[適用例の再現手順](../../benchmarks/communication-design-pilot/README.md)と[検証記録](design-pilot-results.md)を参照。

- 「2〜4項目」「中央揃え」「左右対称」「一定色数」などを絶対条件にしない。
- 装飾、固定の図解分類、営業提案向けの順序をあらゆる資料に強制しない。
- 図を整えるための情報削除、データ追加、根拠のない因果・順位を認めない。
- 動きによる提示順は静止画の読み順へ応用した。アニメーション機能は実装していない。

品質向上の判定は[比較検証の手順](design-evaluation.md)に従う。ガイドの追加、技術的な検査の通過、作例の完成だけで成功とは扱わない。
