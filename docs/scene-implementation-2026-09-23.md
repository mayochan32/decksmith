# シーン方式の初期実装と検証

2026-09-23。固定構図の分類・座標分岐を廃止し、AIが設計したsceneを共通の描画処理へ渡す経路に置き換えた。

## 実装

- 任意のスタイルYAMLの意味解釈とページ設計はプラグインのSkillを読むAIが行う。
- 元のYAML・構成のSHA-256を設計へ記録し、変更時の使い回しを防ぐ。
- 全スタイル末端項目を解釈台帳へ対応づける。未解決項目や無効な対応先を拒否する。
- 描画はtext/shape/path/imageの要素列。任意の座標、寸法、書体、色、部分強調、回転、前後関係を保持する。
- ページ数・順序・必須文字列を検証し、5項目目以降も保持する。
- 画像は資料内の相対パスで参照する。存在しない画像・未知の要素やキー・意図が記録されていないはみ出しはエラーにする。
- 初期アダプターが対応していない専用表/グラフ、マスク、グループ変換は明示的な制約。別の表現へ黙って置換しない。
- 自動検査と視覚検査を区別し、生成直後の台帳はpending_visual_review。
- PyYAML 6.0.3の純Python版をMITライセンス付きで同梱。ホストのPyYAMLやプラットフォーム固有バイナリに依存しない。
- 旧入力形式向けの例示YAMLは削除した。以前の資料と開発成果物はartifactsに残し、配布プラグインから呼び出さない。削除した追跡済み例示ファイルはGit履歴から復元可能。

## 縦断検証

同じ3ページ（表紙、5工程、比較）を3つの簡略化したスタイル仕様で設計した。sceneはこの制作時にAIが作成し、描画エンジンのスタイル分岐は追加していない。

| 仕様 | 検証した変化 |
|---|---|
| 赤いエディトリアル | 巨大な左寄せ文字、括弧付き番号、赤と明るい背景の分割 |
| 黒板 | 背景素材、丸い日本語書体、中央配置、5つの円、補助色 |
| 今回初めて与えた日本語の制作ノート | 独自キー、右下の小さい明朝タイトル、広い空白、縦の工程、上下の比較 |

全9ページのPNGを個別に確認し、文字切れや意図しない重なりがないことを確認した。PPTX内の文字と位置も読み取り、5つ目の工程と異なるタイトル位置を確認した。PowerPointアプリ自体で開いての確認はしていない。

これらは今回の簡略化した検証仕様に対する合格であり、以前提示された完全なYAMLや参考PDFに対する品質合格を示さない。黒板背景は以前の資料からプロジェクト内へコピーした。新規画像生成の工程は今回実行していない。

## 配布経路の検証

/private/tmp内へ配布用skillsとmanifestだけをコピーし、別の資料ディレクトリから実行した。日本語の通常のYAML（JSON表記ではない）を同梱のパーサーで読み、PyYAMLを持たないバンドルPythonでPPTX生成に成功。元の作業場所と移動先の3ページのPNGはバイト単位で一致した。

これは同一マシン上の移動検証。別OS・別マシン・別ホスト製品へのインストール試験ではない。ホストから取得するPresentationsランタイムと利用可能なフォントが必要。

## 検査結果

- 自動テスト16件成功（未知キー、未解釈指定、内容欠落、元ファイル変更、画像欠損、配置保持など）。
- 実際のPPTX出力を使う追加テスト1件成功。部分強調、別書体、回転角、カスタムパス、画像と文字の前後関係をXMLで確認。
- Skill/プラグイン検証成功。
- 新たな外部公開・インストール・Gitへのコミットやpushはしていない。

## 次の評価対象

元の3スタイル全文と参考PDFを使い、題材固有の新規生成画像も含めて美観を評価する。今回の検証用sceneをプリセットとして使い回さず、その都度YAMLから設計する。画像と文字の質感統一、必要な表/グラフ、複雑な切り抜き・マスクは、実際の要求と検証結果に沿って拡張する。
