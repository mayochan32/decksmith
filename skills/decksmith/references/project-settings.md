# 制作設定 decksmith.yaml

外部ツールや画像生成を使う前に、指定された設定ファイルまたは資料フォルダー直下のdecksmith.yamlを確認する。ファイルは任意で、プロンプトだけでも指定できる。

```yaml
slide:
  width_px: 1920
  height_px: 1080
  aspect_ratio: "16:9"
privacy:
  mode: restricted
input:
  style: style.yaml
  brief: brief.md
output:
  directory: output
  filename: presentation.pptx
  pdf: true
images:
  mode: auto
  amount: normal
  type: auto
  color: color
  plan: show
language: 日本語
```

## 読み取りと優先順位

scripts/project_config.py --config <project>/decksmith.yamlで検証済み設定をJSON表示できる（通信なし）。相対パスは設定ファイルの親フォルダー基準。inputは存在するローカルファイル。設定がなければ資料フォルダーで同スクリプトを引数なしで実行できる。

既定は1920×1080、normal、auto、output/、PDFなし。filenameは題材からAIが決める。style/briefは依頼・添付から、languageは依頼内容から判断。比率のみは長辺1920px、比率と片方の寸法はもう片方を算出。片方の寸法だけなら16:9で補完。両寸法がある場合は16:9に戻さない。

プロンプトや任意形式のスタイルYAMLにある制作条件もAIが解釈する。明確な上書き指示は優先するが、矛盾が曖昧なら確認。画像要求からprivacy制限解除を推測しない。

プロンプトで変更した設定は元ファイルを残し、資料フォルダー内のdecksmith.resolved.yamlへ同じ設定スキーマで記録して--configで渡す。保存先が異なる場合はパスを絶対パスへ変換し意味を保つ。サイズをstyle/プロンプトから読み取った場合もslideに記録する。設定解決は設計前に行い、確定したサイズ・言語・モードを利用者へ伝える。

create_deck.pyはsceneと同じフォルダーのdecksmith.yamlを自動検出する。別ファイルは--configで指定する。--style、--outputは明示上書きに使えるが、利用者の指定なく設定と違う値にしない。サイズはscene.canvasとの一致を検査。不一致ならsceneを再設計し、設定を改変して検査を回避しない。

## 言語

languageは空でない自由な文字列。ja、日本語、en、English、english、英語などをAIが解釈する。地域指定（繁體中文、ブラジルのポルトガル語、イギリス英語）も保持する。Pythonで限定リストに変換しない。不明な言語は勝手に別言語へ戻さず確認する。本文・見出し・キャプション・説明用ノートに適用し、固有名詞や引用原文は必要に応じて保持する。最終レビューでも指定言語を確認する。

## 外部サービス制限

restrictedでは利用中のAIサービスの組み込み機能（画像生成を含む）とローカル処理のみ許可。Web検索・外部URL閲覧・素材取得・外部API・外部ストレージへの送信操作は禁止。同じ提供会社でも別途接続するAPIは組み込み機能と扱わない。送信先不明のツールは使わず確認する。自動でnormalにしない。

初回セットアップの取得は対象外。制作中の追加ダウンロードは行わず不足を案内して停止する。ローカルツールが内部で別サービスを呼ぶ場合も禁止。ローカルモデルは導入済みのものだけ使用。

「原稿・画像・プレビューは利用中のAIサービスへ送信され得る。別サービスは使わない」と説明する。これはAIの操作ルールでありネットワーク遮断機構ではない。OS同期や拡張の通信を制御する保証はしない。実際のツール利用・例外・未確認事項をreview.jsonへ記録する。project_settingsの記録だけで遵守を証明したと扱わない。

## 画像

autoは必要に応じて提供画像か生成画像を選び、privacyを優先する。provided_onlyは利用者が指定した画像のみ使用し、新規画像生成・外部取得はしない。指定画像のローカル加工、編集可能な図形・図解は可能。

提供画像は画像認識が利用可能なら実際に見て内容・構図・比率を把握し、スライド内容と照合して配置する。利用者の配置・加工禁止指定が優先。人物名や型番は見た目から推測しない。画像認識が使えなければ説明を求める。合わない画像を無理に使わず、不足時は追加素材または代案を相談する。

## 画像方針と生成前計画

画像の枚数や配置をPythonが決めるのではなく、AIが以下を解釈して設計する。

- amount: normal（既定）は内容理解や印象づけに効果があるページ、moreは各ページで積極的に活用を検討、lessは必要性の高いページに限定、noneは画像を生成・取得・配置しない。枚数に加えて面積や役割を考える。小さいアイコンの大量配置でmoreを満たさない。noneでも説明用の編集可能な図形・図解・グラフは可能だが、装飾イラストを図形で描く迂回はしない。
- type: auto（既定）、illust（イラスト）、photo（写実的）、icon、anime。提供された証拠画像や製品写真を勝手に作風変換しない。photoの生成画像を実写の記録として説明しない。
- color: color（既定）はスタイルに合う複数色を使える、grayは黒白グレー、monotoneは基調色など単一色相の濃淡。画像だけに適用し、本文や背景の色を一律に変更しない。colorは多色を強制しない。
- plan: show（既定）は計画をチャットへ提示して承認待ちせず進む。confirmは計画を提示して利用者の明示承認を待ち、承認前に画像生成・取得・加工やPPTX生成を実行しない。skipは提示だけを省略し、内部の計画・レビューは省略しない。計画変更で承認内容が変わった場合は再確認する。

brief.mdのページ別の有無・量・種類・色調・配置指定は、そのページでdecksmith.yamlの全体画像方針より優先する。全体noneでもbriefで表紙画像が明示されていれば表紙だけ使える。ただしprivacyとprovided_onlyはページ指定から解除しない。不足素材や矛盾は相談する。明確なプロンプトの訂正指示は優先し、不明なら確認する。省略された既定値でスタイルの明示指定を打ち消さない。

プロンプトの「普通／多め／少なめ／画像なし」はnormal/more/less/none、「イラスト／写実的／アイコン／アニメ／おまかせ」はillust/photo/icon/anime/auto、「カラー／白黒／モノトーン」はcolor/gray/monotone、「画像計画を確認してから」はconfirmへ解釈する。YAMLの列挙値は上記の英語だけを受け付ける。briefの自由文もAIが解釈し、元の記述を保持する。

原稿・提供画像を読んだ後、素材制作前にimage-plan.mdを資料フォルダーへ保存する。各ページのid、画像の有無と目的、量・面積の目安、種類・色調、提供素材か生成か、適用したページ指定とその出典を記録する。noneのページは画像なしの理由も記録する。show/confirmではその要約をチャットへ示す。confirmの承認内容・計画変更も記録する。生成後は計画と実際の画像を照合しreview.jsonに結果を残す。承認や画像の意味を描画エンジンが自動検証したとは説明しない。

## 出力ファイル

output.pdf=trueならPPTXと同名PDFを保存。falseでも品質確認用PNGは作る。PDF・PPTX・プレビューの既存出力は上書きしない。filenameは.pptx付きでディレクトリー成分なし。input.briefを読んで内容を設計し、input.styleをデザインに適用する。描画処理そのものは原稿の要約や翻訳を行わない。
