# 画像素材の接続契約 v1

画像生成サービスを描画エンジンに組み込まない。制作AIが利用可能なホスト機能または利用者が許可した外部サービスを呼び、結果を資料内assets/に保存する。生成サービスのAPIキーや開発チャットの画像は同梱しない。

必要な各素材についてasset-requests.jsonへ次を記録する:
- id: 資料内で一意の素材ID
- prompt: 被写体、スタイル、質感、構図、文字安全域
- width / height: 希望ピクセル寸法
- reference_paths: 資料内に保存した参考画像の相対パス（なければ空配列）
- output_path: assets/内の新しいPNGまたはJPEGの相対パス
- consumers: 使用するslideID/elementIDの配列

生成後はasset-results.jsonへid、実際のpath、provider（実際に使った機能名）、model（判明している場合）、sha256、生成プロンプト、参考画像、確認結果を記録する。希望寸法と実寸法の差も記録する。既存素材を黙って上書きしない。

ホストから一時パスで返された素材は資料内へコピーする。生成したこと・ファイルの存在・画像の表示可能性・構図の適合を確認した後、sceneのimage.pathへ接続する。PPTXには画像のバイト列を埋め込むので生成サービスへの接続は不要になる。

本文、数値、正確なラベルは画像に焼き込まずネイティブ文字として描画する。素材生成前に文字領域と被写体領域を設計する。文字が画像に埋もれる問題が続く場合は色・位置の微調整を繰り返すだけでなく、トリミング・文字領域の分離・構図の変更を検討する。固定の構図プリセットは持たない。

## 生成できない場合

機能なし・利用上限・生成失敗で必要画像が用意できない場合は、理由と対象ページを伝え、(1)画像なしで再配置、(2)予定画像位置に四角を置き中に画像生成プロンプトを編集可能な文字で記載、のどちらかを人間に確認し回答を待つ。一部だけ成功した場合は失敗分について確認する。images.plan=show/skipでも省略できない。無回答で省略・図解置換・別サービス接続をしない。外部サービスの承認と画像代案の選択は別の判断。

選択・理由・対象・人間の回答根拠を.policy.jsonのimage_fallbacksへ記録する（形式は[制作補助](workflow.md)）。omitではレイアウトを再設計し、全体images.amountを無断でnoneにしない。placeholderでは実際の構図・被写体・スタイルを含むプロンプトを四角内に読みやすく収める。必要なら短く再記述し、完全版もasset-requests.jsonに残す。画像を実装済みと偽装せず、該当スタイル要件は承認根拠付きapproved_alternativeで扱う。納品とレビューのdelivery_statusはawaiting_imagesとし「画像差し替え待ち」を明示する。画像まで完成した資料とは称さない。

このバージョンはホスト経由の接続手順を共通化する。OpenAI/Anthropic/Googleの画像APIを自動選択して呼ぶアダプターは含まない。任意YAMLの内容をシェルコマンドとして実行しない。
