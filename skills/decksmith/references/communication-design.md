# 内容から図解と読み順を決める

座標を決める前と、描画後のレビューで使う判断基準。完成レイアウトのカタログではない。利用者の原稿・ページ数・文字量・スタイルを優先し、このガイドのために情報を削除したり、すべてのページを図解化したりしない。

## 先に伝える関係を確かめる

各ページで、聞き手の問いと、原稿が実際に答えられることを一文ずつ考える。構成指定がある場合はその順序を保つ。結論が未確定なら「何が未確定か」を伝え、強い見出しを作るために断定しない。

素材の使用制限、推測の禁止、確認手順などの制作条件は、聞き手へ伝える本文と区別する。「推測しない・計算しない」をそのまま注記にせず、解釈に必要な限界を原稿の根拠に沿って「この集計からは求められない」など読者向けの説明へ直す。原因を推測できないことを「因果関係がない」と断定しない。「自動延長ではない」「事前承認が必要」など、利用者が守る実際の条件は残す。作り手の作業宣言をスライドの結論にしない。

図解が有効なページでは、要素を取り出し、**何と何が、どう関係するか**を原稿に照らす。その後に表現を選ぶ。項目数や見た目だけで図を選ばない。以下は意味を見分ける問いであり、選べる図の限定リストではない。

| 原稿から確認すること | 表現の候補と確認点 | 避ける誤読 |
| --- | --- | --- |
| 独立した項目か | 一覧・まとまり。等価な項目は同程度に扱う | 並べただけの項目に矢印を加えて手順にする |
| 同じ対象を同じ観点で比べるか | 対応する行・基準・単位を揃えた比較 | 片側だけ条件を省き、優位に見せる |
| 時間や処理が進むか | 順序・始点・終点を示す。期間も重要なら尺度を持つ時間軸 | 左右の順序を因果関係と断定する |
| 元の段階へ実際に戻るか | 戻り先と条件のわかる循環・フィードバック | 円形配置だけで循環を意味させる |
| 分配・統合・選別なのか | 向きと接続先、入力・出力・条件を示す | 分岐と合流、集約と因果を混同する |
| 所属・支持・順位のどれか | 関係を明記した階層・包含。面積が数量かも区別 | 協力関係を上下関係にする。段階を量の大小に見せる |
| 共通部分が実際にあるか | 重なりの意味を説明できる交差・集合 | 関連があるだけの概念をベン図にする |
| 二つの軸で位置を決められるか | 軸の意味・尺度・配置根拠を持つ座標図 | 4項目だから四象限にする。右上を無条件に優位にする |
| 中心と周囲、複数主体が関わるか | 中心の役割・線の意味・方向を区別した関係図 | 全結合や双方向の矢印を根拠なく追加する |
| 数値の何を読むか | 比較・推移・構成比など目的とデータに合うグラフ | 都合のよい範囲・面積・立体効果で差を誇張する |

手順や受け渡しを図にするときは、同じ枠を並べる前に、**誰が行うか／何をするか／何が渡るか／どの状態で終わるか**を原稿から区別する。主体、行為、成果物、完了状態を同じ見た目で混ぜると、「利用者が完了する」「成果物が次の担当者である」などの読み方が生じる。必ず別の図形種を割り当てる必要はなく、文字のまとまり、見出し、位置、区切りによって役割が読めればよい。矢印も、担当の移動、資料の受け渡し、状態の変化のどれを結ぶか確かめる。

条件や動作の説明は、それが適用される接続や対象の近くへ置く。戻った後の再処理を離れた補足へ置き、読み手に接続を推測させない。描画後は図のラベルと線だけをたどり、主語・対象・終点が一通りに読めるか確かめる。新しい役割や判断条件を補って曖昧さを埋めず、原稿にある関係の配置と言葉を直す。

手順図では、始点から主要な受け渡し・終点までをまず線だけで追う。上下の往復や読み戻しが多い場合は、主な流れを一つの方向へ揃え、例外や戻りをその外側へ分ける案を比較する。横一列や同じ大きさの箱を既定にせず、説明の長さと分岐の位置に必要な余白を取る。戻りの条件と、戻った人が何を直してどこへ再提出するかは、同じ経路を読む場所へまとめる。空白を埋めるために段階や線を足さず、文字を縮める前に主経路と説明の場所を組み直す。

線の交差、途中で接する線、長い重なりは、接続・合流を誤読させないか見る。原稿にない交点を関係として解釈せず、意図した分岐・合流ならその条件と行き先を確認する。交差を避けるために正しい接続を省略しない。

関係がない、短い主張だけで十分、画像そのものが証拠、といった場合は図解を選ばなくてよい。写真・表・引用・文章にも役割がある。ネイティブ表・グラフが必要な場合の実装条件はSKILL.mdに従う。

数値や条件の比較では、[数値と条件の設計](native-evidence.md)も読む。何を比較するのか、項目・数値・単位・期間・条件を原稿から取り出し、その元データを表示文と別に保持してから表現を選ぶ。差の大きさを読むグラフ、条件を照合する表、具体的な場面を示す写真は役割が異なる。写真を添えただけで数値の比較を説明できたと判断せず、軸や対応する行を画面から追えるようにする。

最初に把握するまとまりを少なくすると見通しを作りやすい。ただし「2〜4項目」は整理の検討材料であって上限ではない。6つの独立した必須条件を、見た目の都合で3つへ削ったり、意味のない上位分類を作ったりしない。まとめるなら原稿中の共通性を根拠にし、各項目への対応を残す。

## 図の意味を、スタイルに合う画面へ変える

[構図の選択と資料全体の流れ](composition-design.md)に従い、主役の配置から画面を組む。以下の「主役」は大見出しと同義ではない。

- **主役**：最初に理解すべき主張・差分・関係を目立たせる。必ず一つの図形だけを大きくする必要はなく、比較の一組も主役になる。章番号や装飾が主張に勝っていないかを見る。
- **読み順**：主役、根拠、条件を追える配置にする。矢印は視線誘導の飾りではなく、内容上の方向を表す。静止画でも関係を理解できるようにする。
- **揃えと余白**：関連するラベルや比較対象の基準線を揃え、まとまりの間に区切りを作る。字面の揃いも画像で確認する。全面対称・全要素同間隔を強制しない。
- **色の役割**：基調・補助・強調の役割を決め、同じ意味の色をページ間で維持する。利用者の多色・モノクロ等の指定を尊重し、色だけに意味を預けない。
- **統一と変化**：書体の役割、線、色、素材の扱いに共通性を持たせる。内容が比較から手順に変われば配置は変えてよい。同じカード列の反復で統一を代用しない。
- **数値と証拠**：注目箇所を強調しても、母数・期間・単位・条件・出典を隠さない。概念図の位置や大きさを測定値のように見せない。イメージ写真を実績の証拠にしない。

## 見出しと強調を画面へ反映する

見出しだけを順に読んで、各ページの主題・違い・つながりがわかるかを見る。手順や前提は明確な題目が役立ち、数値比較では原稿に支えられた観測結果を見出しにできる。すべてを断定文や問いに揃えたり、目新しさのために原因・効果・年間傾向を作ったりしない。良い既存見出しは残す。

見出しの要点に対応する表の行、図の経路、グラフの系列・項目を選び、位置・余白・文字・線・色の必要な差を実装する。すべてを強調しない。同格の比較対象を一方だけ強くして原稿にない優位を示さず、例外を弱める場合も成立条件を読めるまま残す。表のセルと棒グラフの点は[ネイティブ強調](native-evidence.md)を使える。強調を必要としないページに追加しない。

同じ説明が表、本文、脚注に重なっていれば、読み手に必要な場所へまとめる。表の両列に共通条件を残すなど、比較を正確にする反復は維持する。重複検出だけを理由に削除せず、必須内容・条件が画面で読めることを再確認する。

既存communicationメモへ必要な参照を加えると、design-checks.jsonのreading_outlineに実際の見出し、宣言した要点・原稿の根拠、対象要素、強調スタイル、前後とのつながりが並ぶ。これを描画前の言葉だけの流れと、描画後の画面の照合に使う。機械が意味や良し悪しを判断する機能ではない。

## 説明文を意味のまとまりで配置する

補足が複数あるページでは、それぞれが何を説明する文かを先に確かめる。同じ主張を補う文章は段落としてまとめ、図の注意はその図に結び付けるなど、読む場所と対象の対応がわかる形を選ぶ。文字の間隔だけを詰めても、関連する補足がページの各所に残っていれば分散は解消しない。

説明の置き方には、たとえば次の候補がある。組み合わせや別の構図も選べる。

| 内容上の必要 | 配置の候補 | 確認すること |
| --- | --- | --- |
| 一つの図や主張を、複数の文で通して説明する | 共通する補足を一つの本文領域へ集約し、段落・小見出し・太さで区切る。図固有の注記は図の近くへ置く | 主役から補足へ進んだあと、続きの文を探さず読めるか |
| 図の各部分と説明を個別に対応させる | 対象の近くへ短い説明を分散して添える | どの説明がどの部分に属するか明確か。図を横切る長い文や、遠くの凡例との往復が増えていないか |
| 複数の対象の差を読む | 各対象に説明を添え、比較する項目の順序と基準を揃える | 一か所へ集めることで対応関係を失っていないか。共通条件は比較全体に属すると読めるか |

これらは選択肢であり、「大きな図を左、説明を右」などの既定配置や、題材から自動選択する型ではない。毎ページに説明欄を作る必要もない。集約する場合も、文章を一つの小さな文字塊に押し込まず、主説明・補足・注記の階層と読める文字サイズを保つ。図の存在感や有効な余白が損なわれる場合は、本文の位置や集約範囲を見直す。配置と採用理由は既存のcompositionまたはcommunicationへ短く記録する。

## 設計とレビューに短く記録する

design-plan.yamlの各slidesに、既存のfocal_reason/compositionと重複しない範囲で、自由記述のcommunicationメモを加える。機械が意味を検証するスキーマではない。

```yaml
communication:
  audience_question: 誰が次の担当を決めるのか
  takeaway: 受付が担当を決め、未解決の案件だけが受付へ戻る
  relationship: 受付から担当への割当と、未解決時のフィードバック
  source_basis: 原稿「運用案」の担当と差し戻し条件
  representation_reason: 矢印に条件を添え、通常経路と戻りを区別する
  reading_order: 主張 → 受付と担当 → 戻る条件
  avoid_misreading: 解決済みの案件まで循環させない
  headline: <見出しを表示するtext要素のID>
  visible_evidence: [<要点を支える実在要素のID>]
  emphasis_targets: [<強調を実装した要素のID>]
  continuity: 前ページの担当説明を受け、ここでは未解決時の戻り先を具体化する
```

図解不要ならrelationshipを「関係図なし」とし、理由を一文で十分。記録を埋めるために関係や項目を作らない。

headline/visible_evidence/emphasis_targets/continuityは任意の参照・メモ。headlineは同じページのtext、残りの参照配列は同じページの実在要素を重複なく指す。visible_evidenceを使う場合はtakeaway/source_basisも記録する。古い自由記述はそのまま利用でき、見出しや強調が不要なページへ無理に追加しない。グラフの個別点や表のセルの選択はsceneのhighlightsに記録する。

描画後はプレビューから「何がわかったか」と「画面のどの事実・例・関係でそう読めたか」を短く書き、設計時のtakeaway・原稿と照合する。設計メモの意図を、画面から読み取れた証拠として転記しない。同じAIによる確認は独立した読者テストではない。

見出しが答えでも、理解に必要な具体例や関係が画面になければ、言葉の言い換えを並べただけになる。「比較の基準」のような補助語の大きさ、箱の整列、構図の種類数では補えない。説明を要するページでは、どの差・接続・変化が主張を支えるのかを見えるようにする。単独の主張・引用・写真で成立するページに説明図を強制しない。伝わらない場合は表示文の編集と図の選択へ戻る。

| 確認 | 実際に記録する証拠の例 |
| --- | --- |
| 意味 | 「未解決」の矢印だけが受付に戻り、完了への経路と区別できる |
| 主役・読み順 | 比較対象の対応行を横に追え、差分のあとに条件が読める |
| 判読性・揃え | 日本語ラベルが線から離れ、同じ役割の開始位置が揃っている |
| スタイル | 原稿指定の明朝見出しとモノクロの線を保ち、一般的な青いカードへ置換していない |
| 資料全体 | タイトル列から問いと答えのつながりが追え、同じ項目の色や呼称が途中で変わらない |

review.jsonの既存content/legibility/styleのevidenceへ書く。意味の誤りはcontent、読みにくさはlegibility、指定表現との違いはstyleで区別する。採点の平均で内容の欠落や誤った関係を相殺しない。
